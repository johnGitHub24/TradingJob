JOB-A — 逾時未成交取消

  • StaleOrderTimeoutJob @Scheduled cron。
  • StaleOrderCancellationService 找逾時 NEW 訂單。
  • 狀態轉 CANCELLED + 寫 order_events。
  • 手動觸發：JobController 同 Service 路徑。
flowchart LR CRON["@Scheduled JOB-A"] --> SOJ[StaleOrderTimeoutJob] HTTP[POST /jobs/...] --> JC[JobController] SOJ --> SOS[StaleOrderCancellationService] JC --> SOS SOS --> OR[OrderRepository]

Scheduler 只呼叫 Service，不含商業邏輯。

JOB-B — PnL 日結快照

  • PnlSnapshotJob 定時執行。
  • PnlSnapshotService 彙總持倉／PnL。
  • 寫入 pnl_snapshots 表。
  • 與 Engine 共用 DB schema（正式環境）。
flowchart LR CRON2["@Scheduled JOB-B"] --> PSJ[PnlSnapshotJob] PSJ --> PSS[PnlSnapshotService] PSS --> PR[PositionRepository] PSS --> SN[PnlSnapshotRepository]

本機 dev：H2 :8084，不假設 Engine 已啟動。

JOB-C/D — DLQ 重試與清理

  • JOB-C：FailedCommandRetryJob → DLQ 重放。
  • OrderReplayPort 可選 HTTP 呼叫 Engine。
  • JOB-D：DataCleanupJob 清理舊 events／failed_commands。
  • 保留天數由 JobProperties 設定。
flowchart TB FCJ[FailedCommandRetryJob] --> FCS[FailedCommandService] FCS --> FCR[FailedCommandRepository] FCS --> ORP[OrderReplayPort] ORP --> ENG[Engine HTTP optional] DCJ[DataCleanupJob] --> DCS[DataCleanupService] DCS --> EV[order_events cleanup]

詳述 docs/Task用法.md 排程設定。

Runtime — 排程與分層

  • ThreadPoolTaskScheduler pool-size 預設 4。
  • dev :8084 H2；prod :8083 PostgreSQL。
  • 分層：api / application / scheduler / client / infrastructure。
  • 驗證：.\gradlew.bat check。
