# 驗證設計 — TradingJob

> 衝突以 [TradingJob-SPEC.md](../TradingJob-SPEC.md) 為準。  
> 規範：EngineeringOS `knowledge/validation-design.md`  
> **本專案無 JWT／角色矩陣**（Job 服務偏內部／本機觸發）；重點在業務規則與資料約束。

## 四層

| 層 | 機制 | 典型失敗 |
|----|------|----------|
| L1 傳輸 | HTTP Method／Content-Type；Actuator health 公開 | 405／400 |
| L2 格式 | 查詢參數（如 `date`、`status`）型別綁定 | 400 |
| L3 業務 | 逾時門檻、重試上限、批次大小、清理保留天數（`JobProperties`） | 空批次／達 max-attempts 終態 |
| L4 資料 | UK／狀態欄位（orders、failed_commands 等） | 約束衝突（應少見） |

## 權限矩陣

| 端點 | 公開（目前） |
|------|----------------|
| `POST /api/v1/jobs/*` | ✅（無 Security Filter；部署時應置於內網／閘道後） |
| `GET /api/v1/pnl-snapshots` | ✅ |
| `GET /api/v1/failed-commands` | ✅ |
| `/actuator/health` | ✅ |

## 業務規則摘要

| Job | 規則 |
|-----|------|
| JOB-A | `timeout-seconds`、`batch-size` 內取消逾時未成交 |
| JOB-B | 依持倉寫當日快照 |
| JOB-C | `max-attempts`、`backoff-seconds`；經 `OrderReplayPort` 重放 |
| JOB-D | 事件／失敗指令保留天數後刪除 |

## 對照程式

- API：`JobController`
- 設定：`JobProperties`、`SchedulingConfig`
- 重試：`FailedCommandService`
