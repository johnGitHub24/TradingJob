# TradingJob 註解規範

> 權威：EngineeringOS `eos-minimal/knowledge/comments.md` @ 0.1.5  
> 本專案宣告：`comment_verbosity: detailed`

## 為什麼是 detailed？

本專案是 **排程 Job 教學／練習**（與 Engine 共用 DB），註解要讓初學者看懂：

1. **【職責】** 這個 Job／Service／方法在業務上做什麼  
2. **【技巧】** 用了哪個 Spring／JPA／排程 API（`@Scheduled`、`TaskScheduler`、Port／Adapter…）  
3. **【概念】** 為什麼這樣寫、和「塞進 Controller／同步 API」差在哪  

涵蓋四條 Job：

| Job | 職責摘要 |
|-----|----------|
| JOB-A | 逾時未成交訂單自動取消 |
| JOB-B | PnL／持倉日結快照 |
| JOB-C | 失敗下單指令重試（DLQ） |
| JOB-D | 過期審計事件與終態失敗指令清理 |

一般業務專案請改為 `brief`，避免註解過長。切換方式見公版 §7。

## 套用範圍

| 路徑 | 深度 |
|------|------|
| `src/main/java/**` | detailed（public 型別／業務方法） |
| `src/test/java/**` | detailed（類別檔頭；方法至少 CASE／Given-When-Then） |
| `scripts/*.ps1` | 檔頭用途／何時跑／成功標準 |
